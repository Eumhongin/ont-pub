# ont-pub: RAG 적재 전 문서 형태와 RAG 파이프라인

BGE-M3 · bge-reranker-v2-m3 · pgvector 로 한국어 RAG 를 만들 때의 설계 정리입니다. 임베딩 모델과 리랭커는 바꾸지 않는다는 전제입니다.

| [02. RAG 파이프라인](02-rag-pipeline.md) | 질의부터 답변까지의 단계, 단계별 파라미터와 필요 여부, sparse 가 없는 환경의 BM25 |

## 요약

- **청킹 전:** PDF·HWP·DOCX·HTML 을 모두 같은 정본 형태로 바꿉니다. 정본은 제목 계층, 블록 종류, 원본 위치, 메타데이터를 가집니다.
- **청킹:** 길이 상한은 BGE-M3 토큰으로 재고, 자르는 위치는 문서 구조로 정합니다.
- **검색:** Dense(q1)·Dense(q2)·Sparse(q1) 세 목록을 RRF 로 합치고 bge-reranker-v2-m3 로 다시 매깁니다. sparse 가 없으면 ParadeDB BM25(공백을 지운 2-gram)가 Sparse(q1) 자리를 맡습니다.
- **답변:** 리랭커 임계값, Parent 확장, 위치순 병합, 토큰 예산, 출처 번호로 컨텍스트를 조립하고 인용을 강제합니다.

## 용어

| 용어 | 뜻 |
| --- | --- |
| 정본 (canonical document) | 파싱과 후처리를 마친, 청킹 직전의 표준 문서 형태 |
| Contextual Chunk Header | 임베딩·리랭킹 입력에서 청크 앞에 붙이는 문서 제목과 섹션 경로 |
| RRF | 여러 검색 목록의 순위를 1/(60 + 순위)의 합으로 합치는 방법 |
| 골든셋 | 실제 질문과 정답 청크를 짝지은 평가 자료 |
| 2-gram | 글자를 2개씩 한 칸씩 밀며 자른 토큰. `환불요청` 은 `환불`·`불요`·`요청` |

## 범위

- 두 문서는 벡터 RAG 를 다룹니다. 온톨로지(개체 종류·관계·제약을 정한 스키마)는 다루지 않습니다.
- 정본의 메타데이터와 스칼라 프리필터가 나중에 온톨로지와 이어지는 자리입니다.
